---
title: Limitations
description: What HooriDB cannot do yet.
---

HooriDB is in early development. The list below covers what it cannot do yet.

## Table data

- A table tab grid edits, inserts, and deletes rows only in tables with a primary key (see [Table data](/docs/features/table-data#edit-insert-and-delete-rows)). In an [SQL console](/docs/features/console#edit-query-results), single-table `SELECT` results with a primary key support updating existing cells only: a new row may not match the query, and the console does not run the query again after a commit, so deleted rows would still show.
- You cannot filter or sort rows in the grid.
- A table grid displays at most 2,147,483,647 rows, and copying from a grid is limited to 100,000 selected cells at once from rows that are already loaded.
- Values longer than 1,024 characters can be fetched whole in the value panel only for tables with a primary key and for MongoDB collections (by the document's `_id`). In tables without a primary key, and in SQL console results, the value panel shows only the first 1,024 characters.

## Databases and platforms

- Only PostgreSQL, MySQL, MariaDB, and MongoDB are supported.
- Only Windows 11 or later (x64, Direct3D 12) and Linux (x64, glibc 2.38 or later, Vulkan) are supported. macOS, ARM builds, web, and mobile are not supported.

## Browsing and schema management

- The Workspace tree shows databases, schemas (on PostgreSQL), tables, views, and columns. It does not list indexes, constraints, sequences, functions, triggers, or other objects.
- There is no visual editor for creating or altering tables, columns, or schemas.

## SQL console and history

- In **Auto** mode with no open transaction, plain read queries load as you scroll. Other console results, and every result in **Manual** mode or while a transaction is open, are read whole before they appear and keep only the first 100,000 rows of each result.
- Running a `USE` statement in SQL does not update the **Database** dropdown in the console toolbar.
- On PostgreSQL, code completions assume the default search path (`"$user", public`) and do not follow custom `search_path` settings. Tables in system schemas appear in completions only after you expand them in Workspace.
- Statements longer than 64 KB are not recorded in History, and History keeps at most 1,000 statements per connection.
- You cannot copy rows from the **Messages** tab.
- There is no SQL formatter or visual query plan viewer.

## Import and export

- [Import and export](/docs/features/import-export) handle tables and views of PostgreSQL, MySQL and MariaDB only, not MongoDB collections, and not a console's query.
- Export writes CSV, TSV and JSON, one file per table. Import reads CSV and TSV into a table that exists. There is no SQL `INSERT`, XML or `xlsx` format, no table created from a file, no update of rows by their key, and no saved settings to run again.
- With several tables checked, every column is exported, in the table's order.
- Moments are written in UTC. A PostgreSQL date before the common era is written with ISO 8601's year numbering, such as `-0001-01-01`, which PostgreSQL does not read back.
- A table whose storage engine keeps no transactions, such as MyISAM, cannot be imported into.
- In a CSV or TSV file of one column, every empty line is a row, also one at the end of a file that was written by hand.

## MongoDB

Some of these limits are tracked in [issue #57](https://github.com/hooridev/HooriDB/issues/57).

- Connections support a single host and port, or a `mongodb+srv://` host. Host lists are not supported, and the options a `mongodb+srv://` host lists in its DNS TXT record, such as `replicaSet` or `loadBalanced`, are not read. Pasting a connection string with multiple hosts or options without a field uses the first host and supported options and lists the rest under **Host**.
- Only user name and password authentication (SCRAM) is supported: no X.509 certificates, LDAP, Kerberos, or AWS IAM, which authenticate against `$external`.
- Pages are read by offset, ordered by `_id`. On a view that projects out or duplicates `_id`, documents can repeat or be skipped between pages.
- A collection's fields in the tree and grid come from a sample of 100 documents, so fields absent from that sample do not appear there; **JSON** and **Tree** still show them.
- The console parses [shell statements](/docs/features/mongodb#run-shell-statements-in-a-console) without JavaScript: variables, functions, and loops are not supported.
- There are no transactions in a MongoDB console.
- A collection's tab edits, inserts, copies, and deletes [one document at a time](/docs/features/mongodb#edit-insert-copy-and-delete-documents) in a dialog: not cells in the grid, not several documents at once, and not a console's result; an `_id` cannot be changed. The check for a document changed meanwhile does not see a value whose type alone changed while it compares equal: a number of another type at the same value, such as `1` to `Long('1')`, or a string turned into a symbol of the same text.

## Connections and appearance

- **Read-only** on PostgreSQL, MySQL, and MariaDB uses the server's read-only transactions, which do not cover everything a statement can do (see [SQL console](/docs/features/console#read-only-connections)):
  - Statements that act outside the tables still run, such as advisory locks (`pg_advisory_lock`, `GET_LOCK`), `NOTIFY`, `VACUUM`, `ANALYZE`, and `CHECKPOINT` on PostgreSQL, `ANALYZE TABLE` on MariaDB, functions that reach outside the transaction, as through `dblink`, and `COMMIT PREPARED` (PostgreSQL) or `XA COMMIT` (MySQL and MariaDB) of a transaction that another session prepared.
  - `SET` still changes the session's other settings.
  - HooriDB finds a statement that would turn read-only off by its text. It does not see one put together at run time, such as a setting's name joined from two strings, nor an existing function, procedure, or trigger that turns it off; after such a statement, the session can write.
  - For a hard limit, log in as a user who has only read permissions.
- There is no built-in support for SSH tunnels, client TLS certificates, or custom driver parameters.
- Connections cannot be imported or exported from the UI.

## Updates

- Built-in updates work only when running from an installed app image (Windows installer, Windows zip, or Linux tar.gz) where your user account can write to both the app folder and its parent.
