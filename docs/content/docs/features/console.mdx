An SQL console gives you an editor, result tabs, a Messages log, and transaction controls on a dedicated server connection. A console on a MongoDB connection runs shell statements instead, without transactions; see [MongoDB](/docs/features/mongodb#run-shell-statements-in-a-console).

<Shot name="console" alt="An SQL console with two SQL statements in the editor and Result 1, Result 2, and Messages tabs below" />

## Open a console

Open a new console in any of these ways:

- Right-click a connection in Workspace and choose **New console**.
- Choose **File > New console** or press `Ctrl+N` (opens a console for the connection selected in Workspace, or for the active tab's connection if no connection is selected in the tree).

The console opens its own server connection when you run your first statement, so a slow query does not block browsing the tree or reading table tabs.

HooriDB saves open console tabs (their text, connection, and selected database) about one second after you edit them, and reopens them unconnected the next time you start HooriDB. Closing a console tab removes its saved text.

## Switch databases

Choose a database from the **Database** dropdown in the console toolbar. The list contains the databases that Workspace has loaded for that connection.

If the console has an open transaction, HooriDB asks what to do with it before switching databases. Running a `USE` statement inside the SQL editor does not update the **Database** dropdown.

## Run and cancel statements

- Press **Run** or `Ctrl+Enter` to run the selected SQL, or the single statement at the caret if nothing is selected. The editor marks the lines of the statement that `Ctrl+Enter` will run.
- Press **Run all** or `Ctrl+Shift+Enter` to run every statement in the editor from top to bottom, stopping at the first error.
- Press **Cancel** while a statement runs to cancel it on the server. Rows already read stay visible in the result tab. When you cancel or disconnect during a change, it may already have taken effect; if HooriDB says the outcome is not known, check the data before running the statement again.

## Read results and Messages

Each statement that returns rows or changes rows creates a result tab (**Result 1**, **Result 2**, and so on) below the editor.

- Statements that modify rows show the count of affected rows (for example, `1 row changed`).
- In **Auto** mode with no open transaction, plain read queries load rows as you scroll down. Other results, and every result in **Manual** mode or while a transaction is open, are read whole before they appear, keeping the first 100,000 rows, and HooriDB asks first when the server estimates more (see [Transactions](/docs/features/transactions)).
- A result's columns open as wide as their header and first rows; rows read later as you scroll leave the widths as they are.
- Press **Pin** (the pin icon in a result tab's footer) to keep that result tab across future runs. Press **Unpin** to allow the next run to replace it.
- Press `Shift+Enter` or the **Value** button in a result tab's footer to open the [value panel](/docs/features/table-data#inspect-a-cell-in-the-value-panel) for the selected cell. A console result keeps up to 1,024 characters of a value and cannot read more from the server.
- Select cells and press `Ctrl+C` (or `Ctrl+Insert`) to copy from a result grid.
- Open the **Messages** tab to see every statement run in the console, how long it took, and its result, warnings, or errors.

## Find errors in the editor

<Shot name="console-error" alt="A console showing an unknown column error underlined at line 4 with the error message below the editor and logged in Messages" />

When a statement fails and the server reports where the error occurred, HooriDB underlines that location in the editor, moves the caret there, and displays the server's message above the results tabs. The underline clears as soon as you edit the text.

## Read-only connections

Check **Read-only** next to **Access** in the connection dialog to keep a PostgreSQL, MySQL, or MariaDB connection from changing data. As it connects, HooriDB makes every session of the connection read-only at the server: the Workspace tree's, each console's, and the one it uses for row estimates. Switching databases keeps it.

- The server refuses statements that write to tables or change the schema, such as `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`, `CREATE`, `ALTER`, `DROP`, and `GRANT`, in **Auto** and **Manual** mode alike. Its error, such as `cannot execute INSERT in a read-only transaction`, appears above the results and in **Messages**, as any other error does.
- Temporary tables are refused too, and on PostgreSQL so is `nextval()`.
- HooriDB does not send a statement that would turn read-only off for the session: one that names the read-only setting (`default_transaction_read_only` or `transaction_read_only` on PostgreSQL, `transaction_read_only` or `tx_read_only` on MySQL and MariaDB), also in a string, one with `READ WRITE`, on PostgreSQL `RESET ALL` and `DISCARD ALL`, on MariaDB `SET SESSION AUTHORIZATION`, and on MySQL `CREATE TABLE … START TRANSACTION`. To read the setting, use `SHOW transaction_read_only`, or `SHOW VARIABLES LIKE 'transaction_read_only'` on MySQL and MariaDB.
- **Commit** and **Rollback** still end a transaction, which holds its snapshot and locks until then. HooriDB still asks before an `UPDATE` or `DELETE` without `WHERE`, which the server then refuses.

What the server does not refuse this way is listed under [Limitations](/docs/reference/limitations#connections-and-appearance). A MongoDB connection is read-only in its own way; see [MongoDB](/docs/features/mongodb#read-only-connections).

## Complete SQL keywords and names

<Shot name="completion" alt="A console editor showing column name completions and data types after typing an alias and a dot" />

The completion list suggests SQL keywords for your database dialect along with schemas, tables, views, and columns for the console's database.

- The list opens automatically from the second letter of a word, or right after typing `.` following a schema, table, or alias name.
- Press `Ctrl+Space` anywhere in the editor to open the list manually.
- Press `Enter` or `Tab` to insert the highlighted item, or `Escape` to close the list.

Names that require quoting are quoted automatically for PostgreSQL (`"..."`) or MySQL and MariaDB (`` `...` ``).

If a database's tables or a table's columns have not been loaded in Workspace yet, HooriDB reads them automatically when completions ask for them. Keep typing or press `Ctrl+Space` again to see the newly loaded names.
