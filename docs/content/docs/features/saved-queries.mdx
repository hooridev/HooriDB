---
title: Workspace queries
description: Keep SQL and MongoDB queries in Workspace folders and run them on any matching connection.
---

A workspace query is a reusable SQL or [MongoDB](/docs/features/mongodb) shell query stored right beside your connections in the [Workspace](/docs/features/workspace) tree (`workspace.json`). Unlike [History](/docs/features/history), which records statements run on a specific connection, a workspace query is not tied to a connection, database, or schema — you can run the same query against local, staging, or production.

## Create a query

You can add a query to Workspace in two ways:

1. Press **+** in the Workspace toolbar, open the **File** menu, or right-click a folder, and choose **New query…**. Enter a **Name**, choose **SQL** or **MongoDB**, and press **Create**. The new query goes into the selected folder, or into the folder of the selected entry.
2. From an open console, select the text to keep (or leave nothing selected to keep the whole console text) and press **Save to workspace** in the toolbar. Enter a **Name** and press **Save** to create the query in the folder of the console's connection.

## Open and edit a query

Double-click a query in Workspace, select it and press `Enter`, right-click it and choose **Open**, or find it by name in the [command palette](/docs/features/command-palette) after `@` (`Ctrl+P`).

- HooriDB opens one tab per query; opening the same query again raises its existing tab.
- The tab shows the query's name and takes the color of its current target connection.
- Until you choose a target connection, SQL queries use dialect-neutral standard SQL highlighting and statement splitting, and completion offers the keywords all servers share.
- Edits are saved automatically into `workspace.json` about one second after you stop typing, and when you close the tab or exit HooriDB.
- Query tabs left open when you exit reopen automatically at the next start, unconnected, with their last target connection remembered for the **Run on** menu.

## Choose a target connection and run

Run a workspace query the same way as any console: **Run** (`Ctrl+Enter`), **Run all** (`Ctrl+Shift+Enter`), or a statement's gutter marker.

- On the first run, HooriDB opens a menu at the caret listing every connection of the query's language (**SQL** or **MongoDB**): the last target first, with a check mark, then the other connected ones, then those not connected. Each row shows the connection's color mark, folder path, and whether it is **Read-only** or **Not connected**.
- Move with `Up`/`Down` or type a connection's first letter, and press `Enter` (or click a row) to run. Press `Escape` to cancel without running anything.
- Choosing a disconnected connection connects it first, then runs the query.
- Later runs run directly without asking only when **exactly one** connection of that language is connected and it is the last target. Otherwise, the menu opens again with the last target first, so a query never silently moves to another connection.

## Switch target connections

When you choose a different connection from the menu:

- If the tab has an open transaction or pending result edits, HooriDB asks first using the console's usual confirmation dialog.
- HooriDB ends the old session, clears all result tabs (including pinned results) so results from the previous server cannot be committed to the new one, resets **Database** to the new connection's default, and runs the query on the new target.

## Organize and delete queries

Rename, duplicate, move (via **Move to** or drag and drop), and delete work the same way as for connections in [Workspace](/docs/features/workspace). Deleting a folder counts its queries alongside its connections; **Delete contents** deletes them and closes their open tabs (asking first if any has an open transaction or pending edits).
