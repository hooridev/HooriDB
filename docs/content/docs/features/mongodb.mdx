HooriDB connects to MongoDB through the official MongoDB Java driver. A MongoDB connection lives in the [Workspace](/docs/features/workspace) like any other: it has a color, a password in the system keyring, a tree, table tabs, consoles, and [History](/docs/features/history). This page covers what is different.

## Connect to MongoDB

1. Open the connection dialog (see [Your first connection](/docs/get-started/first-connection)) and choose **MongoDB** as the **Type**. The **Port** changes to `27017` unless you already edited it.
2. Enter the **Host** and **Port** of one server. HooriDB connects only to that server, as the shell does when given a single host; host lists are not supported.
   - For a `mongodb+srv://` address, as MongoDB Atlas gives, check **Servers from DNS** next to **SRV** and enter the host of the address, such as `cluster0.example.net`. The **Port** is hidden, as DNS lists the servers and their ports, and **TLS** changes to **Encrypted, any certificate** unless you already chose it. Options in the address after the host, such as `?appName=…`, are not used.
3. Optionally enter a **Database**. Consoles start in this database, or in `test` if you leave it blank.
4. Choose the **TLS** setting, as for the other types.
5. Check **Read-only** next to **Access** if you want HooriDB to send only read commands on this connection (see below).
6. Enter the **User** and **Password**, or leave **User** empty for a server without access control (if HooriDB still asks for a password, press **Connect** with the field empty). Users are authenticated against the `admin` database, which covers MongoDB Atlas and users created in `admin`; users created in another database cannot log in yet.

The first time you connect or test, HooriDB asks before downloading the MongoDB Java driver. See [Drivers](/docs/features/drivers).

## Read-only connections

With **Read-only** checked, HooriDB sends only read commands and refuses all others before they reach the server:

- `find`, count commands, `distinct`, and commands that list databases, collections, and indexes or report statistics and server information.
- `aggregate`, as long as no pipeline stage (including in nested pipelines) is `$out` or `$merge`.
- `explain` of any of these.

Inserts, updates, deletes, index changes, drops, and commands HooriDB does not recognize are refused with a message in the console (for example, `The connection is read-only: insertOne may change data and was not sent.`). Read-only is a safeguard in HooriDB, not a server permission; for a hard limit, log in as a user with read-only permissions.

## Browse databases and collections

Expanding a MongoDB connection in the tree shows its databases, then their collections and views, then the fields of each collection.

- The databases your user can see are listed; `admin`, `config`, and `local` are shown in muted text. Collections whose names start with `system.` are omitted.
- Views show an eye icon, as in SQL databases.
- A collection's fields come from a sample of 100 documents (or the first 100 when the server cannot sample, such as for some views). `_id` comes first and is marked as the key; every other field shows the types it held in the sample, such as `string` or `int | null`. A field that some sampled documents lack is shown as nullable.

**Refresh** reads the sample again. Fields absent from the sampled documents do not appear in the tree or the grid.

## Look at a collection's documents

Open a collection or view as you open a table (double-click it, or select it and press `Enter`). The **Show documents as** switch in the toolbar has three views:

- **Grid**: the fields as columns, read in pages as you scroll, with the same paging buttons, row count, copying, and [value panel](/docs/features/table-data#inspect-a-cell-in-the-value-panel) as a table. A document or an array in a cell is shown as Relaxed Extended JSON, which the value panel formats and colors when the field holds only documents or arrays. A value shortened in the grid is read whole by its document's `_id`.
- **JSON**: 200 documents at a time as a formatted array of Relaxed Extended JSON. The paging buttons in the status bar move between pages, as in the grid.
- **Tree**: the same 200 documents, each as a tree of its fields.

Documents are read in pages ordered by `_id`. The status bar shows the document count just as a table tab shows the [row count](/docs/features/table-data#row-count-and-paging-controls); press **Count documents** for an exact count.

## Run shell statements in a console

**New console** on a MongoDB connection opens a console for MongoDB shell statements. HooriDB parses them itself without JavaScript and sends each as a server command; `use` and `db.getName()` are handled locally by HooriDB. Statements end at a semicolon or at the end of a complete line. You run them the same way as in an [SQL console](/docs/features/console) (the statement at the caret, the selection, or all statements), with **Cancel**, Messages, pinned results, History, and consoles kept across restarts.

The console understands:

- `db.<collection>.find(…)` (with `sort`, `limit`, `skip`, `projection`, `hint`, `collation`, `count`, `itcount`, and `explain`) and `findOne`.
- `aggregate`, `countDocuments`, `estimatedDocumentCount`, and `distinct`.
- Write methods: `insertOne`, `insertMany`, `updateOne`, `updateMany`, `replaceOne`, `deleteOne`, `deleteMany`, and the `findOneAnd…` methods, with their options. An option the console cannot send is refused instead of dropped.
- Indexes (`createIndex`, `getIndexes`, `dropIndex`, and others) and `drop`.
- `db.runCommand(…)`, `db.adminCommand(…)`, `db.getName()`, `db.getSiblingDB('<database>')` (for calls on another database, such as `db.getSiblingDB('<database>').<collection>.find(…)`), `use <database>`, `show dbs`, and `show collections`.

For a collection whose name is not a valid shell identifier, use `db.getCollection('name')`.

Results that return documents have the same **Grid**, **JSON**, and **Tree** switch as a collection tab. **JSON** and **Tree** show 200 documents at a time with the same paging buttons; the next page reads more documents while the result's cursor is open (running the next statement closes it), and the last page is known once the cursor is read to its end. An insert, update, replace, or delete shows how many documents it changed; the `findOneAnd…` methods show the server's reply.

`use <database>` switches the console's **Database** for the statements after it. You can also choose the database from the **Database** dropdown in the toolbar.

### Errors and completions

- A statement HooriDB cannot parse is underlined where the error occurs, and the caret moves there, just like a server error in an SQL console.
- Completions suggest collections after `db.`, collection and cursor methods, `$` operators, and the collection's sampled fields.

### Updates and deletes of every document

Before an `updateMany` or `deleteMany` with an empty filter (`{}`) runs, HooriDB asks whether to update or delete every document in the collection.

### No transactions

A MongoDB console has no **Auto** / **Manual** switch, no **Commit** or **Rollback**, and no transaction state: each command takes effect by itself when the server runs it.

See [Limitations](/docs/reference/limitations#mongodb) for what MongoDB connections cannot do yet.
